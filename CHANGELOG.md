# Changelog

All packages release together with the same version.

## 0.2.0 (2026-10-29)

- `@avgeek-oss/auth-core/hono`: the signed-in person's own sessions. `GET /auth/sessions` lists them newest first with a public `id`, `createdAt`, `lastSeenAt`, `idleExpiresAt`, `expiresAt`, `authenticatedAt`, `browser`, `os` and `current`; `DELETE /auth/sessions/:id` ends one (404 for anyone else's, like an unknown id), and ending the current one signs out; `POST /auth/sessions/sign-out-everywhere` ends all of them, this one included. Session-only, CSRF-checked, and limited by the new `sessions.write` policy (30 a minute per user).
- `@avgeek-oss/auth-core/hono`: the people directory for admins, `GET /auth/admin/users`: every user with role, role source (`claims`, `scim` or `app`), status (`active`, `suspended`, `deactivated` or `deleted`), creation and last sign-in, newest first, paged by an opaque cursor (`limit` up to 100, default 50), with `q` on name and email and a `status` filter. Read-only.
- `@avgeek-oss/auth-core/sessions`: `SessionRecord` gains `publicId`, `lastSeenAt`, `browser` and `os`; `create` takes the sign-in's `userAgent` and stores only its browser family and operating system; `revokeById(publicId, userId)`; `summarizeUserAgent`. Lookups record `lastSeenAt` at most once a minute.
- `@avgeek-oss/auth-core/postgres`: the `0009_sessions_directory` migration: `sessions.public_id`, `last_seen_at`, `browser` and `os`, and `users.last_sign_in_at`, set at sign-in without moving `updated_at`.
- `@avgeek-oss/auth-client`: `sessions.list()`, `sessions.revoke(id)` and `sessions.signOutEverywhere()`, and `admin.users.list({ cursor, q, status, limit })`, with the types `ActiveSession`, `RevokeSessionResult`, `SignOutEverywhereResult`, `SessionsApi`, `DirectoryUser`, `ListUsersInput`, `UserPage`, `UserStatus` and `RoleSource`.
- The reference app shows the person's sessions, with sign-out for each and everywhere.

## 0.1.0 (2026-10-29)

- `@avgeek-oss/auth-core`: typed configuration from `<APP>_*` environment variables, HKDF-SHA256 key derivation with a fixed label registry, 256-bit tokens stored as HMAC-SHA256, the `<prefix>_<id>_<secret>_<checksum>` API key format, the `viewer`/`member`/`admin` roles with claim mapping, actors and typed errors.
- `@avgeek-oss/auth-core/postgres`: the `Sql` interface with `pg` and Postgres.js adapters, a migration runner for plain SQL files, and the `0001_core` migration (users and sessions).
- `@avgeek-oss/auth-core`: `<APP>_OIDC_SCOPES`, and `AuthRequestError` with an HTTP status per code.
- `@avgeek-oss/auth-core/oidc`: the OpenID Connect relying party on `openid-client`, with S256 PKCE, `state` and `nonce`, AES-256-GCM sealed sign-in transactions, the RFC 9207 `iss` check when the provider advertises it, step-up with `prompt=login`, safe `returnTo` paths, claims-to-user mapping (a role only ever comes from the provider), and back-channel logout token verification. The `jti` replay cache is written in the same transaction as the revocation.
- `@avgeek-oss/auth-core/sessions`: sessions with a new token on every sign-in, absolute and idle expiry, revocation, listing and step-up.
- `@avgeek-oss/auth-core/hono`: `createAuth`, with the `/auth` sign-in, callback, sign-out, session, step-up and back-channel logout routes, and the `actor`, `requireActor`, `requireRole`, `requireRecentAuth` and `trustedOrigin` middleware.
- `@avgeek-oss/auth-core/testing`: a mock OpenID provider on `oidc-provider`, with an authentik-like mode, and a cookie-jar browser.
- `@avgeek-oss/auth-core/postgres`: the `0002_sessions_oidc` migration (`users.role_source`, `logout_jtis` and a sessions index).
- `@avgeek-oss/auth-core/scim`: `createScim`, a SCIM 2.0 server for Users and Groups with bearer-token auth, `eq` filters, pagination, attribute selection, PATCH as authentik, Okta and Entra send it, deactivation and tombstoning with `onDeactivate`, revival when the provider provisions a deleted user's `externalId` again, and group membership in `0003_scim.sql`.
- `@avgeek-oss/auth-core`: `<APP>_ROLE_SOURCE` (`claims` or `scim`, roles from SCIM groups recomputed on every membership change with `onRoleChange`) and `<APP>_SCIM_EXTERNAL_ID_IS_SUBJECT`, which links a provisioned user to their first sign-in by `externalId = sub`. Sign-in refuses `unassigned` users in `scim` mode and never-assigned users in `claims` mode.
- `@avgeek-oss/auth-core/api-keys`: `createApiKeys`, personal API keys with a role ceiling and an optional opaque workspace: issue (never above the owner's role), list, rotate with a grace period, revoke, and verify in constant time with the effective role `min(ceiling, role)`. `<APP>_API_KEY_PREFIX`, `<APP>_API_KEY_MAX_TTL_DAYS` and `<APP>_API_KEY_ALLOW_NO_EXPIRY`.
- `@avgeek-oss/auth-core/postgres`: the `0004_api_keys` migration. Deactivating or deleting a user revokes their keys, and lowering their role revokes the keys above it, in the same transaction. A NULL role suspends keys and sessions instead of revoking them.
- `@avgeek-oss/auth-core/hono`: `Authorization: Bearer` API keys in `actor`, `step_up_unavailable` for keys in `requireRecentAuth`, no CSRF check for bearer requests, the `/auth/api-keys` routes, and `hooks.authorizeWorkspace`. `ActorCredential` gains `workspace`; errors gain `step_up_unavailable`, `invalid_request`, `not_found` and `conflict`.
- `@avgeek-oss/auth-core/mcp`: `createMcpAuth`, an OAuth 2.1 authorization server for MCP clients (MCP authorization 2026-07-28): RFC 8414 and RFC 9728 metadata, PKCE S256, RFC 8707 resources with audience-bound tokens, RFC 9207 `iss`, exact redirect matching with RFC 8252 loopback ports, client metadata documents fetched with an SSRF guard, pre-registered clients in `<APP>_OAUTH_CLIENTS`, legacy DCR behind `<APP>_OAUTH_LEGACY_DCR`, the consent and connected-apps APIs, 15-minute access tokens and rotating refresh tokens with reuse detection, RFC 7009 revocation, and `requireMcpToken` with `WWW-Authenticate` challenges. Grants act with `min(ceiling, role)` and follow their owner like API keys.
- `@avgeek-oss/auth-core/postgres`: the `0005_oauth` migration (clients, consent requests, grants, codes and tokens).
- `@avgeek-oss/auth-core`: `ActorCredential` gains `restrictions`; `isValidRedirectUri` and `redirectMatches`; the `oauth-request` key label. The workspace's source export condition is now `@avgeek-oss/source`.
- `@avgeek-oss/auth-core/rate-limits`: `createRateLimiter`, GCRA rate limits in Postgres keyed by HMAC, with `consume`, `check`, `enforce` and `purgeExpired`; the default policies (`DEFAULT_RATE_LIMITS`); and client IP resolution through `<APP>_TRUSTED_PROXIES` and the one forwarding header named by `<APP>_TRUSTED_PROXY_HEADER` (`x-forwarded-for` by default, or `forwarded`), with IPv6 keyed on the /64. `<APP>_RATE_LIMITS` replaces policies by name.
- `@avgeek-oss/auth-core/postgres`: the `0006_rate_limits` migration.
- `@avgeek-oss/auth-core/hono`, `/mcp` and `/scim`: every route reachable without a session is rate limited, plus consent decisions and API key writes per user; failed grants and invalid bearer credentials are counted separately. 429 with `Retry-After` in each route's error shape, never a redirect, and 503 when the limiter's store fails. `auth.middleware.rateLimit` for app routes, `getClientIp` and `rateLimiter` options on `createAuth`, and `rateLimiter` on `createScim`. Errors gain `rate_limited` and `unavailable` (`RateLimitedError`, `RateLimiterUnavailableError`).
- `@avgeek-oss/auth-core/hono`: `auth.middleware.cors`, CORS for pages on another host of the same site. It allows exactly `<APP>_WEB_ORIGIN` with credentials, answers preflights with 204 before authentication, and exposes `Retry-After`. It is on the `/auth` routes, connected apps and the MCP consent routes, and not on SCIM or the OAuth endpoints.
- `@avgeek-oss/auth-client`: a new browser package, released with `auth-core`. `createAuthClient` covers the session, sign-in and step-up URLs, sign-out, API keys, connected apps, MCP consent and the admin views of other people's keys and apps. Every request sends cookies and, except GETs, the CSRF header. Failures are `AuthClientError`s with auth-core's codes, `stepUpUrl` and `retryAfterSeconds`, and unknown codes pass through. `readAuthRedirectError` and `withoutAuthRedirectError` handle `?auth_error=`, and `readAuthError` reads the app's own routes. The wire types match auth-core's JSON. No runtime dependencies, nothing from Node, and a bundle-size budget of 5 KB.
- `@avgeek-oss/auth-client/react`: `AuthProvider`, `useSession` (refreshed on focus and when the page becomes visible), `useRequireRole`, `useStepUp` (navigates to step-up and resumes the action on return), and `useApiKeys`, `useConnectedApps` and `useConsent`. React 19 is an optional peer. No styling; 3 KB budget.
- `@avgeek-oss/auth-core/jobs`: batched sweeps of expired and revoked rows. They cover sessions, logout token ids, consent requests, codes, OAuth tokens, grants and API keys past a 7-day retention, and rate limit buckets. `runAuthJobs` runs them all once within a time budget, for an app's own job runner, optionally `exclusive`. `runAuthWorker` runs them in process on an interval with jitter, one replica at a time under an advisory lock, until an `AbortSignal`. `mcp.purgeExpired` and `rateLimiter.purgeExpired` reuse the sweeps.
- `@avgeek-oss/auth-core`: `checkAuthSetup`, the startup self-check of the provider's discovery document, the client credentials, roles and scopes, SCIM tokens, origins and same-site, migrations and trusted proxies. It returns `{ ok, problems }`, and `failOnError` throws `AuthSetupError` (`setup_invalid`). `createAuth` runs it in the background and logs the summary unless `<APP>_SELF_CHECK=false`, and exposes the report as `auth.selfCheck`.
- `@avgeek-oss/auth-core`: secret rotation with `<APP>_PREVIOUS_SECRETS`. New values use `<APP>_SECRET`. Sessions, API keys, OAuth codes and tokens, consent requests and sealed sign-in transactions made under a previous secret still verify. Sessions and API keys are re-hashed on their next use (`0007_secret_rotation`), and rate limit buckets carry over. `deriveKeys`, `hashTokens` and `Sessions.revokeToken` are new.
- `@avgeek-oss/auth-core/postgres`: the `0007_secret_rotation` and `0008_role_source` migrations; the unused `operator` role source is gone.
